# Security Policy

## Supported versions

Security fixes are prioritized for the latest code on the `main` branch. Older commits, branches, and unreleased snapshots may not receive security updates.

## Reporting a vulnerability

Please do **not** report suspected vulnerabilities through public GitHub issues, discussions, or pull requests.

The preferred disclosure channel is GitHub's **private vulnerability reporting** form on this repository's Security / Advisories page, when that feature is enabled.

If private vulnerability reporting is not available, contact the repository owner through their GitHub profile and request a secure channel before sharing vulnerability details. Do not include credentials, personal data, or an exploit payload in a public message.

Please include, where possible:

- A concise description of the suspected vulnerability and its potential impact.
- Affected branch, commit, component, and environment.
- Reproduction steps or a minimal proof of concept.
- Any suggested mitigation.

Please allow the maintainers reasonable time to investigate and prepare a fix before making the issue public. We will acknowledge reports and coordinate next steps through the private channel used for the report.
