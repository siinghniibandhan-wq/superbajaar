# Security Policy

## Supported versions

Security fixes are prioritized for the latest code on the main branch. Older commits, branches and unreleased snapshots may not receive security updates.

## Reporting a vulnerability

Do not report suspected vulnerabilities through public GitHub issues, discussions or pull requests.

The preferred disclosure channel is GitHub's private vulnerability reporting form on this repository's Security / Advisories page, when that feature is enabled.

If private vulnerability reporting is unavailable, contact the repository owner through their GitHub profile and request a secure channel before sharing vulnerability details. Do not include credentials, personal data or exploit payloads in a public message.

Where possible, include:
- A concise description of the suspected vulnerability and its potential impact.
- Affected branch, commit, component and environment.
- Reproduction steps or a minimal proof of concept.
- Any suggested mitigation.

Allow maintainers reasonable time to investigate and prepare a fix before public disclosure. Reports will be acknowledged and next steps coordinated through the private channel used for disclosure.
